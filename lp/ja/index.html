プッシュ通知のデータを、自社インフラの外に出さない。

push-hub は企業向けのセルフホスト型プッシュ通知配信エンジンです。自社の VPC やオンプレミスにデプロイし、データを SaaS 事業者に渡さずに APNs / FCM 通知を送信できます。

課題

プッシュ通知 SaaS は始めやすい。でも、規模が大きくなるほど割に合わなくなる。

01

データ主権とコンプライアンス

顧客の行動ログ、通知本文、デバイストークンが外部事業者のサーバー、しばしば国外に保存されます。

02

高額な SaaS 利用料

従量課金は配信数に比例して増え、月に数百万〜数億通の規模では大きなコストになります。

03

ベンダーロックイン

配信パイプライン、デバイスデータ、分析のすべてが単一の事業者に依存します。

対象ユーザー

プッシュ通知のデータを第三者に渡せない、渡したくないチームのために。

B2B 企業・セキュリティ重視のスタートアップ

医療、金融、SaaS、行政など、顧客データやプッシュトークンを外部 SaaS に送れない業種。

大規模配信を担う開発・DevOps チーム

月に数百万〜数億通のプッシュ通知を配信し、コストを予測可能にしたいチーム。

データガバナンス・バイ・デザイン

push-hub はすべて自社インフラの中で動きます。

  • データは自社のデータベースに残る。デバイストークン、受信者属性、通知内容、配信ログ、分析データはすべて自社の PostgreSQL に保存されます。
  • 外向き通信は APNs と FCM だけ。テレメトリ、利用統計、クラッシュレポートはどこにも送信しません。
  • ライセンスサーバーなし。ライセンス確認のための外部通信を行わないため、エアギャップ環境でも動作します。
  • どのクラウドでも、オンプレミスでも。必須の依存は PostgreSQL のみ。クラウド固有のサービスは使いません。
  • 標準的なオブザーバビリティ。メトリクス、ログ、ヘルスチェックを Prometheus、Grafana、Datadog、CloudWatch、ELK にそのまま接続できます。

push-hub でも変えられないこと：通知を届けるには、通知内容とデバイストークンを Apple（APNs）または Google（FCM）に送る必要があります。これは SaaS を含むすべてのプッシュ配信サービスで同じです。push-hub は間に入る第三者をなくしますが、Apple や Google を経路から外すことはできません。

アーキテクチャ

シングルバイナリと PostgreSQL だけ。

アプリケーションサーバーが REST API を呼ぶと、api が PostgreSQL にジョブを積み、worker が APNs / FCM に送信します。予約配信は scheduler が担当します。

クイックスタート · プレビュー

docker compose up ひとつで。

イメージはまだ公開していません。これは予定している起動手順のイメージで、現時点では動作しません。本番向けには、マネージド PostgreSQL と組み合わせる Helm チャートを予定しています。

services:
  postgres:
    image: postgres:17
  push-hub:
    image: ghcr.io/aianchor-lab/push-hub:latest
    command: ["all"] # api + worker + scheduler
    ports: ["8080:8080"]
    environment:
      PUSHHUB_DATABASE_URL: postgres://pushhub:pushhub@postgres:5432/pushhub
      PUSHHUB_APNS_KEY_FILE: /run/secrets/apns.p8
      PUSHHUB_FCM_CREDENTIALS_FILE: /run/secrets/fcm.json
$ docker compose up -d
$ curl http://localhost:8080/healthz
{"status":"ok"}
